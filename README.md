# seclave-tools

Libraries and command-line client for the Seclave hardware password
manager's USB-slave wire protocol, in Python and Rust.

A Seclave 2 in its "Usb slave" menu exposes a CDC-ACM serial port. The host
sends length-framed commands; the device answers with unframed responses,
and the user approves each secret read on the device's own screen - that
confirmation, not host software, is the security boundary.

## What is in here

| Directory | Package | What it is |
|---|---|---|
| `python/seclave/` | [`seclave`](https://pypi.org/project/seclave/) on PyPI | The protocol as a Python library: framing and parsing, serial transports (Linux/macOS/Windows), a session class with one method per device command, and a stub device for tests (`seclave.testing`). Stdlib only. |
| `python/seclave-ctl/` | [`seclave-ctl`](https://pypi.org/project/seclave-ctl/) on PyPI | Command-line client built on the library: `list`, `get`, `put`, `del` and the web-login (`-www`) variants. |
| `rust/seclave/` | [`seclave`](https://crates.io/crates/seclave) on crates.io | The protocol in Rust. The first release covers the wire format (encoding, framing, response parsing); the transport and session live in seclave-ctl and move down into the library as its API settles. |
| `rust/seclave-ctl/` | [`seclave-ctl`](https://crates.io/crates/seclave-ctl) on crates.io | The same CLI in Rust, a port of the Python one, tested against the same stub device. |
| `vectors/` | - | Shared conformance vectors. Generated by the Python implementation (the reference, validated against real hardware); every implementation's test suite runs them, which is what keeps the ports byte-identical. |

## Install

```
pipx install seclave-ctl        # the CLI (or: uv tool install seclave-ctl)
cargo install seclave-ctl       # the same CLI, Rust build
pip install seclave             # the Python library
cargo add seclave               # the Rust crate
```

On Linux the serial port needs access rights. pip cannot install system
configuration, so the CLI carries the udev rule (ModemManager ignore, user
access, a stable `/dev/seclave`) and installs it on request:
`sudo seclave-ctl udev install` (or `seclave-ctl udev show` to inspect).
The [seclave-companion](https://github.com/seclave/seclave-companion)
deb/rpm ships the identical rule; `dialout` group membership works too.

## Relation to seclave-companion

[seclave-companion](https://github.com/seclave/seclave-companion) is the
desktop GUI. It stays a single self-contained stdlib-only file and does not
depend on these packages; its protocol layer and the Python library here are
the same code, and the conformance vectors hold every implementation to the
same bytes.

## Development

```
python3 python/seclave/tests/test_protocol.py     # library vs stub device
python3 python/seclave/tests/test_vectors.py      # library vs vectors
python3 python/seclave-ctl/tests/test_cli.py      # CLI end to end
cd rust && cargo test          # Rust: unit + vectors + doc, and the CLI
                               # end to end against the same stub device
```

`python3 -m seclave.testing` starts a fake device on a pseudo-terminal and
prints its port path, for developing any client without hardware.

Releases: bump every stamp with `python3 scripts/set_version.py X.Y.Z`,
commit, tag `vX.Y.Z`, push the tag. CI verifies the tag against every
version stamp and publishes to PyPI and crates.io (trusted publishing, no
stored tokens). A `-rc.N` tag runs everything except the registry uploads.
